# Fastfood Kitchen 前端重设计方案（体验重构）

生成日期：2026-08-06
范围：仅前端展示层重设计（web-admin + miniapp）。后端 API、推荐算法、数据库 **零改动**，保留全部资产。

**已确认的设计决策（2026-08-06）**：
- 视觉风格：**极简高效风**（大留白、少装饰、任务与流程突出，Linear/Notion 式）
- 主题色：**保留橙色 #E8530E**（品牌延续）
- 推进方式：**web-admin 与 miniapp 同步推进**

## 一、问题诊断（为什么现在的前端让人失望）

| # | 问题 | 表现 |
|---|---|---|
| 1 | **按数据表组织，不按人组织** | 导航平铺 18 个页面按"基础/运营/配置/系统"分组，厨师长日常工作散落 8+ 页面 |
| 2 | **没有工作台** | 登录后默认落到"食材管理"表格页，无今日待办聚合 |
| 3 | **核心流程被拆散** | 定菜单（推荐/评分/发布）在菜单计划页，但标准/白名单/搭配/反馈分别在 4 个页面 |
| 4 | **配置与操作混排** | 算法参数、标签规则等"设置一次"的页面与每日操作同级展示 |
| 5 | **表格堆砌无引导** | 所有管理页都是 DataTable，缺少步骤引导与状态可视化 |
| 6 | **移动端同样散** | 小程序 21 页平铺，首页是 KPI+菜单+任务+报表的大杂烩 |

## 二、设计原则

1. **以角色的一天为线索**：每个角色登录后先看到"今天要做什么"，而不是菜单列表
2. **工作流优先**：高频流程（定菜单/填报/采购）做成向导式单页，低频配置（算法/标签）收入设置中心
3. **导航三层**：工作台（今日）→ 业务操作 → 设置中心
4. **web-admin 管决策、miniapp 管执行**：桌面端做规划/审批/查看，移动端做填报/确认/查菜

## 三、信息架构重设计

### 3.1 Web Admin 新导航（按角色）

```
┌ 工作台（登录首页，替代现在的第一个表格页）
│   今日待办：未发布菜单 / 未填报经营 / 待审核 / 待收货 / 库存预警
│   快捷入口：按角色显示核心操作
│
├ 业务中心
│   ├ 菜单管理（厨师长主战场）
│   │    今日菜单（向导：选餐段 → 推荐加选 → 评分 → 发布）
│   │    菜单日历（过去 30 天发布记录、评分趋势）
│   │    菜品反馈（剩余反馈汇总 + 菜品表现排行）
│   ├ 采购管理（buyer 主战场，P2 落地后）
│   │    采购需求（菜单反算建议量）
│   │    采购单（草稿/提交/收货）
│   │    价格历史
│   ├ 经营中心（店长）
│   │    每日日报（填报 + 历史）
│   │    经营分析（原 analysis 收敛）
│   └ 数据管理（原 base 分组收敛）
│        菜品库 / 食材库 / 库存查看 / 员工 / 门店
│
├ 设置中心（低频，全部收敛）
│   菜单标准 / 默认菜品 / 搭配规则 / 算法参数 / 菜品标签 / 审核 / 操作日志 / 数据导入
```

角色默认落地页：

| 角色 | 登录后进入 |
|---|---|
| chef_manager / chef / breakfast_chef | 菜单管理 → 今日菜单 |
| store_manager | 每日日报 |
| buyer | 采购需求（P2 前为食材库） |
| prep | 今日任务/库存 |
| admin | 工作台 |

### 3.2 核心页面重设计

**今日菜单（web-admin 最重要的页面）**
```
┌ 日期选择器 + 餐段切换（早/午）
├ 顶部：当前状态条（草稿/已发布/昨日评分 82 分）
├ 中间：三栏布局
│   ├ 左栏：推荐列表（带加成原因、成本、毛利标签）
│   ├ 中栏：已选菜单（按分类分组，显示搭配缺口如"大荤还缺 2 道"）
│   └ 右栏：实时评分卡（完整度/多样性/新鲜度/毛利 4 维度，变化即刷新）
└ 底部：发布按钮（发布后转"出餐模式"只读）
```

**工作台（首页）**
```
┌ 今日概览卡：门店、日期、已发布菜单数、待办数
├ 待办列表（按角色过滤，点击直达）
├ 今日菜单缩略：早/午两段已选菜名
└ 最近经营趋势：近 7 天客单价/人数小图
```

**每日日报（店长）**：填报卡（客单价/人数/天气 + 剩余反馈录入）与历史趋势同页，提交后即时刷新算法影响说明。

### 3.3 小程序重设计

```
├ 首页 → 今日工作台（与 web-admin 工作台对齐）
│    待办卡片：补单 / 填报提醒 / 未完成备料
│    今日菜单（早午分段折叠）
├ 底部 tab：首页 / 菜单 / 填报 / 我的
├ 菜单页：当日菜单 + 补单入口（简化 menu-plan 为"看菜为主"）
├ 填报页：经营数据 + 剩余反馈（原来散在两个页面，合并）
└ 我的：角色信息 + 门店切换 + 设置
```

### 3.4 视觉基线（在已完成的统一工作基础上）

- 圆角 16/20/24/999 四档、阴影两级（已完成）
- 颜色：主色橙 #E8530E（品牌延续）或按偏好重选
- 表格页保留 DataTable（数据管理类页面本就适合表格），但工作台/向导页不用表格

## 四、实施路径（后端零改动）

| 阶段 | 内容 | 工期 |
|---|---|---|
| S1 信息架构 | 路由重组（routes.tsx 分组重构）、导航/侧边栏改造、登录落地页 | 2-3 天 |
| S2 工作台 | 首页待办聚合（API 已有接口组合，无需后端改动） | 2-3 天 |
| S3 今日菜单向导 | 菜单计划页三栏重设计（复用现有 API + 评分接口） | 3-5 天 |
| S4 日报/反馈合并 | store_manager 工作流 | 2 天 |
| S5 小程序对齐 | 首页工作台、填报合并、tab 调整 | 3-4 天 |
| S6 设置中心收敛 | 低频页收进设置分组 | 1 天 |
| 合计 | | ≈ 2 周 |

每一步独立可上线、可回滚；后端接口全部复用，不动算法与数据。

## 五、验收标准（每阶段）

- 对应角色登录后首屏即可完成当日核心任务（≤2 次点击）
- 无跨页跳转完成"定菜单→发布"（原来需 3+ 页）
- 移动端补单/填报 ≤3 次点击
- 视觉统一（圆角/字号/阴影遵循设计令牌）
